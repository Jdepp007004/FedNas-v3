## Phase 2 findings and changes

- The old tier schedule rotated each client through different model sizes. The primary protocol now assigns three fixed capability profiles per seed, capped below the server supernet width, then reuses the same map for all paired strategies. `cc_efl_dynamic` retains the old behavior as a separate diagnostic.
- Added matched controls: `cc_efl_no_prox`, `cc_efl_uniform`, and `cc_efl_random_window`. The random-window control preserves each client's depth/width and model-size sequence while sampling channel offsets independently. Added per-client-capacity validation selections and aggregate deployment metrics so training savings and inference savings are not conflated.
- Added parameter-coordinate coverage and update-frequency statistics; run artifacts now include a split fingerprint, config, source revision/dirty flag, and software/device versions.
- Reviewed Moayedikia & Troncoso Lora (arXiv:2608.07157, 7 Aug 2026). It reports a matched-budget random allocation control, finds that update-based heterogeneity estimates can confound capacity with data, and identifies uncovered coordinates as a failure mode. This directly motivates the fixed-profile matched-window control and explicit coverage metrics. The manuscript must frame these as empirical checks, not claim that capacity-aware allocation itself is novel.
- **Schedule audit (2026-09-28):** the previous systematic channel offset was `(round * width + client_id) % (hidden_dim - width + 1)`. Its per-client cycle can be shorter than the number of valid starts; for `H=128,w=96`, it visits only 11 of 33 legal offsets per cycle because `gcd(96,33)=3`. Changed it to `(round + client_id) % (H-w+1)`, which enumerates every legal bounded start for each fixed client tier over a full cycle. Added a regression test for the 33-position case. The existing v2 systematic-window scores are now historical and must not support final claims; rerun affected methods and regenerate tables/artifacts as v3.
- Novelty audit: FedRolex already provides rolling submodel extraction and claims uniform training exposure; MaxNet already contributes largest-subnetwork priority. A recent 2026 arXiv preprint, **FEAST**, adds multi-variant co-training, in-place distillation, budget-tailored routing, and joint data/budget allocation. A separate 2026 preprint on capacity confounds/coverage guarantees specifically tests matched random allocation. Both are direct nearby work; they make an algorithmic novelty claim for the current CC-EFL integration difficult. Treat both as preprints, not peer-reviewed consensus.
- **Pilot only:** `.benchmarks/phase2_control_pilot.json` is one seed, one round, 120 Digits training examples, and three clients. CC-EFL reached 17.0% aggregate test accuracy vs. 16.0% for FedAvg; systematic-window coverage was 62.1% vs. 66.1% for the random-window control. Active training parameters were 70.3% lower, but the validation-selected deployed model averaged 11.1% more parameters than the FedAvg selections. This pilot is too small for conclusions; it demonstrates why training-resource and deployed-model savings must be reported separately.
- Regression suite: `python -m pytest tests/test_non_medical_benchmark.py -q` → **16 passed** (one upstream `pytz` deprecation warning). This covers fixed profiles, matched budgets, final-only test access in MLP/CIFAR, training-only tabular categories, and deployment-capacity constraints.
- Optimizer fairness audit: SCAFFOLD's drift-corrected update requires SGD, but earlier code silently used 5× the configured learning rate while other strategies used Adam. Removed the multiplier, exposed `--optimizer`, and made the CLI reject SCAFFOLD in an Adam run. The separate SCAFFOLD comparison is now FedAvg/FedProx/SCAFFOLD with identical SGD learning rate and momentum; the primary methods remain Adam. Added a regression assertion for the SCAFFOLD optimizer contract. The same targeted regression suite still passes: **16 passed**.
- Comparison-label audit: the summary's `test_accuracy_mean` was a client-count-weighted score over validation-selected capacity subnets. It was therefore not the full-model FedAvg score. Added separate full-supernet test metrics from the maximum-parameter candidate, kept capacity-selected deployment metrics distinct, and named paired capacity-selected deltas explicitly. Correctly processed the raw 20-round Digits output into `.benchmarks/phase2_digits_adam_20r_5seeds_v2_reported.json`; the training data/results are unchanged.
- Runtime control: a one-thread repeat of the Digits 20-round FedAvg seed 1 matched the default-thread run exactly on both capacity-selected accuracy (0.63852) and full-model accuracy (0.96444). Its per-run wall clock fell from 35.55 s to 7.11 s. The runner now exposes and records `--torch-threads`; use one thread for subsequent CPU runs.
- Added an exploratory `cc_efl_fjord` extension that combines CC-EFL's fixed rolling windows and weighting with FjORD-style ordered-width local distillation. It is deliberately not in the registered primary matrix until its paired results justify retaining it.
- Corrected 20-round Digits comparison: summary reporting now distinguishes the full supernet from client-capacity deployment. The full FedAvg model is 97.0%; its validation-selected post-hoc capacity slices average 65.8%. CC-EFL is 89.7% full and 77.3% capacity-selected. This prevents a sliced deployment score from being mislabeled as full-model FedAvg.
- Ran the primary Adam matrix for five seeds on Digits (20 rounds), Adult (10), Bank Marketing (10), and HAR (8): `fedavg`, `fedprox`, `heterofl`, `fjord`, `fedrolex`, `maxnet`, `cc_efl`, `cc_efl_random_window`, and `cc_efl_fjord`. Ran `cc_efl_no_prox` and `cc_efl_uniform` on all four tasks. Artifacts and full tables are in `RESULTS.md` and `.benchmarks/phase2_*_v2*.json`.
- Cross-task summary: CC-EFL capacity-selected primary endpoint versus capacity-sliced FedAvg was +11.5 accuracy points on Digits (95% CI +5.5 to +17.5), −3.87 macro-F1 points on Adult (−12.74 to +5.00), +0.68 macro-F1 points on Bank (−5.57 to +6.94), and +11.58 macro-F1 points on HAR (+0.96 to +22.20). This is mixed performance, not a reliable cross-task win. FjORD had the best mean endpoint on Digits and HAR; HeteroFL and FjORD led Bank; random-window CC-EFL significantly exceeded systematic CC-EFL by 7.21 Adult macro-F1 points (95% CI +1.30 to +13.13). ## Fixed-client-budget model-width scaling — 2026-09-28

- Added `run_model_scaling_benchmark.py` with separate fixed and proportional capacity-scaling modes. Fixed mode expands the server supernet and evaluation candidate while preserving each client's original capability tiers; it keeps the full supernet out of the client capacity menu.
- Ran HAR at widths 96 and 384 for five seeds/eight rounds, comparing FedAvg, HeteroFL, FjORD, FedRolex, MaxNet, and CC-EFL. The client tiers remained 24/48/72. CC-EFL's selected macro-F1 was .8321 at width96 and .8036 at width384. At width384, the server model has 813,318 parameters while heterogeneous clients averaged 31,974 active parameters and estimated forward FLOPs were 96.1% lower than full-width FedAvg. CC-EFL is below FjORD (.8572), MaxNet (.8466), and HeteroFL (.8418) at that scale.
- Ran width768 for three seeds/eight rounds with the same fixed client tiers. The server model has 2,806,278 parameters (10.705 MiB of FP32 weights); heterogeneous clients remain at 31,974 average active parameters (0.122 MiB of FP32 weights), a 98.9% estimated active-parameter/FLOP reduction versus full-width FedAvg. CC-EFL macro-F1 is .7459 (seed-level 95% CI .6825–.8093); its paired change vs capacity-selected FedAvg is +.1197 (95% CI −.0019 to +.2413), descriptive only. FjORD is higher at .8282; MaxNet .7913; HeteroFL .7825.
- Full-supernet quality degrades as the supernet expands: CC-EFL's full-width macro-F1 is .8612/.8216/.7300 at widths 96/384/768, versus full-width FedAvg at .9059/.8956/.8824. This is the decisive scale-up caveat: the capacity-selected smaller deployments hold up better than the fully expanded CC-EFL model, but low coverage means the large global model is not adequately trained.
- Ran a matched random-window CC-EFL control at widths 384 (five seeds) and 768 (three seeds). Resource use is identical to systematic CC-EFL. At width384, random windows raise coverage 9.3%→45.3% but reduce macro-F1 .8036→.5845 (paired random-minus-systematic −.2191, 95% CI −.4133 to −.0249, unadjusted). At width768, coverage rises 2.7%→23.6%, but macro-F1 is .4636 vs .7459 (paired −.2823, 95% CI −.6681 to +.1034). Random offsets improve coverage while hurting short-horizon utility; the wider-model result is uncertain.
- Final validation for the scaling runner: `python -m pytest tests/test_non_medical_benchmark.py -q` → **20 passed** (one upstream pytz deprecation warning); `python -m compileall -q non_medical_benchmark` passed; all five scaling JSON artifacts parsed and had the expected 154 total run records; fixed-tier heterogeneous rows consistently recorded 31,974 average active parameters and 1,023,168 upload bytes/round. `git diff --check` reported no whitespace errors (only existing LF-to-CRLF notices).
- Scaling limitation: after eight rounds, CC-EFL coordinate coverage falls from 81.4% at width96 to 9.3% at width384 and 2.7% at width768. This verifies that a larger server model can execute with unchanged client tiers in the simulator, but most of the expanded supernet is untouched within this short schedule. The other subnet methods also show very low coverage at expanded widths. Do not claim a fully trained, high-quality larger global model from this probe.
- The separate proportional-width run `.benchmarks/model_scaling/har_widthscale_1_4_8r_5seeds.json` grows client capacities too (active mean from 31,974 to 200,454 parameters between 1× and 4×); do not use it to claim constant client resource needs.
- Machine was Windows 11 / Python 3.13.7 / PyTorch 2.9.0 CPU, with no CUDA device. FP32 parameter bytes and forward FLOPs are modeled estimates; wall-clock is single-process simulation time. No physical edge peak-memory, energy, or network measurement was collected.
- Full tables, commands, and caveats are in `RESULTS.md`; raw artifacts are in `.benchmarks/model_scaling/`. The scaling CI is not a registered non-inferiority analysis and no scaling comparison received multiplicity correction.
